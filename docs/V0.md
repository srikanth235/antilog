# V0 design decisions

Owner decisions of 19–20 Nov 2026. Where a skill, ruling or board disagrees, this page wins until the skills are rewritten to match it.

## Sessions copy Claude Code cloud sessions

- **Runner polls a queue.** The server keeps one queue of sessions. An `antilog runner` (target) on any host polls it over outbound HTTPS, claims a session with a lease, clones the repos, starts the harness as a child process and streams its events back. Nothing connects inward. This replaces the `Platform` trait, the stepping relay and every agent-platform adapter (AgentCore, Claude Managed Agents, the OpenAI Agents API, Foundry, Google Agent Runtime).
- **One machine per session.** A VM with Docker inside, so the agent can run the whole solution. Default 2 vCPU and 4–8 GB; an environment may ask for more. On Antilog cloud: one spot VM per session, paused when idle, reaped after a maximum lifetime, a cap on concurrent sessions per organization. No NAT gateway.
- **OpenCode is the harness.** The only one in v0, pinned to one version in the session image. The runner writes OpenCode's machine-wide config (provider, the `antilog` MCP entry, permissions, skills folders), which a repo cannot override, and drives it over its HTTP API. Other harnesses come later through the same runner.
- **Environments.** A network level (none, limited with allowed hosts, full), plain variables, secrets and a setup script. The setup result is snapshotted and reused; a snapshot expires after 7 days unused.

## The proxy

One proxy outside the session machine does three jobs:

1. **Model gateway.** The customer brings their model keys, saved per organization per provider and never sent into a session. The harness's base URL points at the proxy, which swaps the session's short-lived token for the real key, forwards without translation, books spend from each response's token counts and refuses calls once the experiment's budget is spent.
2. **Network allowlist** for the session's outbound traffic.
3. **Secrets** attached to requests for listed hosts.

## What the agent can reach

- **One MCP endpoint per session**, served by our server: the judge's tools plus the tools of every connector switched on. Connector credentials stay on the server. Each tool is on, off or ask first (an approval card).
- **Skills** are organization skills with fixed versions, in `SKILL.md` folders. The runner copies the experiment's selected skills into OpenCode's skills folder. The receipt lists the versions.
- **Plugins** are an Antilog bundle (skills, connectors, evaluation templates). Adding one unpacks it into those parts, each governed as usual. Harness-native plugins are later.

## Testing

The test runs inside the session's own machine. The judge takes the number from the sealed test command, not from the agent's report.

## Not in v0

Nested sessions, throwaway cloud environments for testing, harnesses other than OpenCode, translating between model formats, harness-native plugins, a judge sandbox apart from the session machine, Kubernetes and Helm as a requirement.

## Build rule

Delete code that a decision here makes irrelevant in the same change that replaces it. A change is not done while what it replaced is still there.
