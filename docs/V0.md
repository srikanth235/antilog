# V0 design decisions

Owner decisions of 19–20 Nov 2026. The skills follow this page; where a board disagrees, this page wins.

## v0 is cloud sessions only

Owner, 21 Nov: v0 focuses only on cloud sessions, as Claude Code's. Experiments and the judge (seal, measure, trials, holdout, wins, receipts, value) are parked, not redesigned. Projects stay: a project groups sessions, as Claude Code's sidebar groups sessions under a project (owner, 21 Nov). A session belongs to one project and has its repos, environment, model and agent; the sidebar lists projects, each with its sessions under it. A spend cap comes from the organization (monthly cap) with an optional per-session cap. On the orchestrator's recommendation the parked code is deleted rather than hidden, as the build rule asks; the last commit that has it is `daa445f` on `claude/dreamy-ptolemy-vg7uga`, to restore from when the judge returns (the iteration ideas of 21 Nov: a draft stage, diff-based versions, trials that carry across versions, k counted across the experiment, a minimal seal input, a version timeline). Where a decision below names experiments or the judge, it waits with them.

## Sessions copy Claude Code cloud sessions

- **Runner polls a queue.** The server keeps one queue of sessions. An `antilog runner` on any host polls it over outbound HTTPS, claims a session with a lease, clones the repos into the session's machine, starts the harness there and streams its events back. Nothing connects inward. This replaces the `Platform` trait, the stepping relay and every agent-platform adapter (AgentCore, Claude Managed Agents, the OpenAI Agents API, Foundry, Google Agent Runtime).
- **One machine per session, on hosts we keep.** In v0 runners live on a small pool of hosts; the repo has no code that creates hosts, and an agent sets the pool up on demand. A runner locks to one organization when it claims its first session and serves only that organization until it exits, so customers never share a host (as Claude Code's self-hosted runner locks to one owner). Each session runs in its own container on the host, with Docker available inside it, behind a small `Sandbox` trait in the runner so that a microVM or VM backend can replace containers later without touching anything else. Default 2 vCPU and 4–8 GB per session; idle sessions are released and their disk dropped; a maximum lifetime and a cap on concurrent sessions per organization apply (owner, 20 Nov).
- **OpenCode is the harness.** The only one in v0, pinned to one version in the session image. The runner writes OpenCode's machine-wide config (provider, the `antilog` MCP entry, permissions, skills folders), which a repo cannot override, and drives it over its HTTP API. Other harnesses come later through the same runner.
- **Environments.** A network level (none, limited with allowed hosts, full), plain variables and a setup script. In v0 a service key (not a model key) goes in a plain variable, which the agent can read; the screen says so. Network secrets that the proxy attaches without the key entering the machine come after v0. The setup result is snapshotted and reused; a snapshot expires after 7 days unused.

## The proxy

One proxy outside the session machine does two jobs in v0:

1. **Model gateway.** The customer brings their model keys, saved per organization per provider and never sent into a session. The harness's base URL points at the proxy, which swaps the session's short-lived token for the real key, forwards without translation, books spend from each response's token counts and refuses calls once the experiment's budget is spent.
2. **Network allowlist** for the session's outbound traffic, without decrypting it.

## What the agent can reach

- **One MCP endpoint per session**, served by our server: the judge's tools plus the tools of every connector switched on. Connector credentials stay on the server. Each tool is on, off or ask first (an approval card).
- **Skills** are organization skills with fixed versions, in `SKILL.md` folders. The runner copies the experiment's selected skills into OpenCode's skills folder. The receipt lists the versions.
- **Plugins** are an Antilog bundle (skills, connectors, evaluation templates). Adding one unpacks it into those parts, each governed as usual. Harness-native plugins are later.

## Testing

The test runs inside the session's own machine. The judge takes the number from the sealed test command, not from the agent's report.

## No infrastructure tool in the product

The product has no OpenTofu (or Terraform, Pulumi, CloudFormation) concept: no sealed templates, no state it keeps, no module per cloud for customers. When a goal needs infrastructure, the agent writes the files and runs the tool itself inside the session's machine, as it would any other code, with credentials from the environment. The same holds for hosting Antilog cloud itself: the repo has no infrastructure code and no Lambda. The server and the proxy are plain binaries that run anywhere; an agent writes and runs whatever deploys them, on demand (owner, 20 Nov).

## Decisions taken on the orchestrator's recommendation

The owner lets the orchestrator decide where it has a recommendation, without pausing, as long as each decision is written here (owner, 20 Nov). The owner can reverse any line.

- **Environments (E):** variable names `ANTILOG_*` and the `*_PROXY` names are refused; an environment's id comes from its name, so names are unique; sizes are 1 to 16 CPUs and 1 to 64 GiB; the built-in `default` is listed first and its id is reserved; a session whose environment cannot be read gets no network.
- **Platform hosts:** the proxy allows the hosts in `ANTILOG_PROXY_PLATFORM_HOSTS` (the proxy's and the server's public names and the code host) at every network level, so a session at `none` still reaches its model, MCP and git.
- **Runner lock expiry:** a runner's organization lock lapses when the runner has not polled for 10 minutes, so a crashed runner does not hold its organization forever.
- **Session machine limits:** a disk limit per container (20 GiB, where the storage driver supports it), a maximum lifetime per claim (24 hours, then the machine stops, the session waits for a person and a message resumes it), and a cap on running sessions per organization (10 by default, idle machines count, set through `PUT /organization/limits`).
- **Docker for the agent:** only under the sysbox runtime, never `--privileged`; without sysbox the agent has no Docker.
- **Drain:** a stopping runner claims nothing new, waits `--drain-grace-sec`, stops what is left, then exits.
- **Holdout runs in a fresh machine:** a measurement on holdout data never runs in the agent's live machine. The runner starts a second container from the same environment version through the same `Sandbox`, checks out the commits, runs the sealed command with the holdout data, and removes the container. Only that container receives the holdout data or its credential. Measurements on evaluation data stay in the session machine. This is the same kind of machine, not a separate judge sandbox.
- **Holdout machine details:** the fresh machine clones the commits from the code host, so nothing the agent left in its own machine decides the run; a trial commit must therefore be pushed before its holdout run, which the code host work owes. It uses the session's proxy login and is not counted as a session. At start the runner removes any holdout container or network an earlier run left (one runner per host).
- **Bash runs without asking** in the session machine, as in Claude Code cloud sessions: the machine is isolated and reaches out only through the proxy. Edits were already allowed.
- **A decided card reaches the agent at once:** its outcome ("Approved: ...", "Declined: ...") is sent into the session as a message from Antilog, which wakes the agent. An approved repo is cloned into the live machine before that message.
- **OpenCode Zen prices come from Zen's own model list,** fetched without a key and refreshed hourly; time-of-day surcharges are ignored in v0.
- **Platform boards deleted:** `SettingsPlatforms*`, `AddPlatform` and `PlatformError` are gone; the Agents boards point at Model keys instead.

## Not in v0

Nested sessions, throwaway cloud environments for testing, harnesses other than OpenCode, translating between model formats, harness-native plugins, a judge sandbox apart from the session machine, Kubernetes and Helm as a requirement.

## Build rule

Delete code that a decision here makes irrelevant in the same change that replaces it. A change is not done while what it replaced is still there.
