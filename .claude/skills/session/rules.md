# Session: rules that never bend

- Hand credentials to a session only through `request_credential`, never in a prompt, chat message or repo file. In v0 a service key may sit in an environment variable the agent can read, and the screen says so ([docs/V0.md](../../../docs/V0.md)); a model key never enters a session, because a secret there is read by more people than it is meant for.
- Keep credentials out of every response, event, log and tag.
- Give each outside system exactly one translator and stop its vocabulary there, because a second translator forks the meaning of a column.
- Never reshape or pipe data. Build no transform and no pipeline: the customer prepares data in their own warehouse, because a transform layer makes Antilog responsible for data quality it cannot see.
- Keep a connector's credential sealed (`Sealer`, bound to its row), open it only on the server for one call or check, and never send it to a session, a client, an event or a log, because a credential in a machine is read by whatever runs there. A connector is reached only through the session endpoint, over https at a public address, and each call is audited.
- Let a session contact only the endpoints its environment allows, because a machine with open egress can send customer data anywhere.
- Keep a skill pack to written text (size capped, no key in it), because a pack is advice to agents.
- Never let a plugin grant access: a plugin is skills and connectors, each governed as usual, because a bundle has no powers of its own.
- Store none of what a connector returns: the server relays one call's answer to the session and keeps no rows, because the rest can carry customer data.
- Run no loop on the server and keep no step machine. The agent drives. The only server-side state machines are the runner's queue and the budget meter, because a loop on the server decides things a person and an agent should.
- Open a terminal, a file or a preview only in the session's machine, for a person with edit access (read-only for a viewer), and record that it was opened in the audit log, because a shell in a machine is a way into it. Store none of what passes through it.
- Store no file contents, diffs or data. Store the conversation's words, for each tool call a short label with its input and output cut to 4 KB and cleaned of credentials (`ToolRecord::cleaned`; the server cleans again whatever a runner sends), card states, spend and audit rows, because the rest can carry customer data.
- Give each agent its own session, because a shared session leaks one agent's state into another's.
- Privilege no agent's vendor: preselect none by brand. `auto` picks the organization's default agent and says why, and a person can always pick a named one, because a default that favours a vendor ties the customer to it.
- Never give Antilog access to the customer's cloud: no cross-account role, no stored cloud keys. Antilog holds only the customer's model keys (sealed, used only by the proxy) and connector credentials, because access we hold is access that can be stolen.
- Book model spend only in the proxy, from the usage each reply reports (a stream's last usage event; an aborted stream books what was seen and is logged), and refuse a model call once the session's cap, its project's cap or the organization's cap is spent, because a cap that is only advice is not a cap and the harness's own counts are not authoritative. An unknown model is booked at the highest known price.
- Attribute every spend record to its session and agent, because one session must not spend another's money unseen.
- Release an idle or stopped session's machine and drop its disk, because an idle machine is spend with no work.
- Assume every agent can be prompt-injected, and check every tool argument it sends as untrusted input ([threat-model.md](threat-model.md)), because it reads text that people outside the organization write.
- Fail closed: a session Antilog cannot tie to an organization and a project is stopped and deleted.
