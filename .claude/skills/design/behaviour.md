# Behaviour

How a screen behaves. The web app and the macOS app (target; its boards are owed) share behaviour, words and element ids, never pixels. Values are not here: they live in `design/tokens.toml`, and the boards in `design/mockups/` show the result (see [mockups.md](mockups.md)). The words are in [wording.md](wording.md). What an experiment and a session are, what the judge does and what a card asks is in [session](../session/SKILL.md), [judge](../judge/SKILL.md) and [organization](../organization/approvals.md).

## The app is a chat and a judge (target)

The screen follows the product: a person states a goal, an experiment starts, and a coding agent in a session talks to them while the judge's numbers are the only ones that count. There is no mode, no plan step and no separate setup screen. Setup happens in the chat, as a card. Experiments belong to projects, and the sidebar lists them under their project. A session is one agent's work inside an experiment, is named on screen by its agent ("Claude Code session"), and appears in the sidebar only nested under an experiment that is open or pinned.

**Frame.** A fixed 256px sidebar and a main area. Sidebar top (`SidebarTop`): the brand, "New experiment", Search (a link to `SearchStart`, with the ⌘K hint), and the nav rows Projects and Customize. Then `SidebarRows`: Pinned first, then experiments grouped under collapsible project headings (a project heading folds its experiments). Each experiment is one line with a title and one activity icon (what needs you). Under an experiment that is open or pinned, its sessions are nested one level deeper, one line each, named by its agent ("Claude Code session", "Codex session", "Gemini session") with its status icon. Example: the project "Checkout platform" holds "Cut checkout p95 latency" (open, with its three sessions shown), "Speed up the smoke suite" and "Shrink the production bundle"; the project "Search" holds "Autocomplete latency"; the project "Data science forecasts" holds "Reduce forecast error" and "Feature pipeline cost". The user menu at the foot (`SidebarFoot`) has Settings, a quick light and dark switch, the host name and Sign out. `Sidebar` is the three together; `SidebarEmpty` is the same chrome with no rows.

An experiment has a **state**, one word and one icon each: Not sealed, Sealed, Watching, Regressed. It also has an **activity**, which comes from its sessions: Working (an open arc), Waiting for you (a half-filled circle), Done (a check in a circle), Failed (a cross in a circle). Each has a word and its own icon shape, never colour alone. The sidebar row shows the activity icon; the experiment page shows both. A session a person stopped is Done, with the line "Stopped by NAME".

An agent's message in the chat carries the Ratchet mark and the name "Ratchet", with the agent that did the work as a quiet second label ("Ratchet · Claude Code", "Ratchet · Codex" in a spawned session). Agent logos stay where an agent is the subject: spawned session cards, the Agent chip, settings rows, receipts and lineage.

## Page types

Every screen is one of six page types. A new kind of thing under Customize does not make a seventh. The type owns the header, back, search, the empty, loading and error states and the actions; the screen supplies content and words. A screen that hand-rolls any of those is a finding, not a variant.

| --- | --- | --- |

Under it, once the experiment is sealed, the pinned scoreboard strip. Then the conversation: messages, quiet tool lines, cards. A composer docks at the foot and follows the status. Back: none, the sidebar is the way out. Search: global only. States: a card waits until a person decides; a failure is one calm line, never an empty page. Boards: `SessionStart`, `SessionSeal`, `SessionWorking`, `SessionTrials`, `SessionChanges`, `SessionTerminal`, `SessionPreview`, `SessionFiles`, `SessionShare`, `SessionTitleMenu`, `SessionSpawned`, `SessionWin`, `SessionDelivered`, `SessionNoWin`, `SessionBudget`, `SessionCredential`, `SessionRepo`, `SessionRegression`, `SessionFailed`, `SessionReadOnly` | An experiment, in any activity; Home is the Session page type with no conversation yet |

### Session (the experiment page)

The experiment page is the chat of its lead session, one agent in one sandbox on one agent platform with any number of repos attached, under the experiment's header and scoreboard strip. Sessions spawned in the experiment appear as cards in the conversation and open as their own chat inside it, with the breadcrumb "Project / Experiment title / Codex session" (`SessionSpawned`: "Checkout platform / Cut checkout p95 latency / Codex session"). A session has an activity and nothing else; the experiment owns the state, the scoreboard and the budget.

**Header.** One slim bar, described in "Session header and panels" after the composer rules.

**Scoreboard strip.** Pinned under the header once the experiment is sealed; absent while it is Not sealed. It shows the metric from baseline to best ("1,310 ms to 1,102 ms"), trials, kept, and spend of budget ("$42 of $100") with "Change budget" beside it. An editor or owner changes the budget there at any time; lowering it below what is spent stops new measurements. A viewer sees the figure and no control. Beside the numbers is one small chart of the metric per trial, with the baseline and the noise band. When sessions were spawned the chart draws one line per session, each named by its agent, so who is improving is visible at a glance. The chart never shows a number made in a session, only the judge's. A trial being measured is a hollow point. The strip scrolls with nothing; the conversation scrolls under it.

**The conversation.** In order of time:

- Messages from people and from the agent, in short sentences. Text streams as it is written; the agent's message ends with a cursor bar until done.
- Tool calls shown as one quiet line each ("Read 4 files", "Asked the judge to measure"). A chevron expands the line to what was asked and the first lines of what came back.
- **Long tool output** is collapsed and never stored by Ratchet. Opening it fetches it from the platform: the row shows "Fetching from PLATFORM", then the output in a scrolling code block. When the platform has dropped it the row says "This output has expired on PLATFORM." When the platform cannot be reached it says "Can't reach PLATFORM. Output stays there; try again when it is back." with Try again. Neither is drawn as an empty block.
- Cards. A card is the only place structured output appears. There is no step list and no side wizard.

**The composer.** It follows Claude Code's: a rounded box with a soft shadow, and a quiet row of settings. It follows the status. On a session it floats: the conversation scrolls behind it, there is a fade above it and no dock of its own takes a band of the page (every `Session*` board draws this). Home's start composer stays large, because on Home it is the page.

- **One line when idle.** The box starts as one line: "+", the text, then (idle) four small icons for Agent, Environment, Mode and the budget ring, then the mic and send, all on one row. It grows with the text, up to about eight lines, then scrolls inside (`SessionComposerExpanded` draws four lines of text, an attachment and the options row). The options show in full, as the quiet row under the box, on focus or once there is text; idle they collapse to their icons with the budget ring. Every icon has a label and a tooltip.
- **The box, grown**, top to bottom: an attachment strip when something is attached (rounded square thumbnails, an image or a file, each with a remove x on hover; `SessionStart` shows one), the text area (about two lines high on a session, three on Home), and a bottom row: "+" on the left (attach files, images, repos or connectors) and on the right a mic, then send. Typing "/" lists commands. Send is a return-arrow icon, quiet while empty and a filled accent circle once there is text.
- **Under the box**, outside it, right-aligned, quiet text buttons that each open a popover: Project and Repos (Home and a new experiment only; they are fixed once it runs), Agent with its logo and model ("Claude Code · Default", or "Auto" on Home), Environment, Mode and the budget ring ("$42 of $100"; the ring fills with spend). Mode is Ask (every card asks) or Auto (cards that policy allows go through without asking in this experiment; policy still caps it, see [approvals](../organization/approvals.md)).
- A new experiment (`Home`, `HomeEmpty`): the placeholder "What do you want to improve? Type / for commands" and all six settings. Project defaults to the project the person is in (or their last one) and lists the projects where they are an editor or owner. The budget shows the project's default per experiment, falling back to the organization's, and a person can change it. Send starts the experiment. Nothing else is asked.
- **Agent menu** (`SessionAgentMenu`). The Agent button opens a popover above the box: **Auto** first, with one line of why ("Auto would choose Codex: lowest cost per win on Speed experiments here, $18"), then each agent turned on with its logo, a cost tier from "$" to "$$$" and the measured figure ("About $2.70 per trial here"), the current one marked, then a rule and **Hand off to...**, and a note that the figures are measured by the judge on the organization's code. Auto is the default for a new organization once the judge has data; a person can always pick a named agent, and no agent is pre-selected by brand. Before there is data Auto uses the organization's default agent. Home shows "Auto" in the row. Existing session boards keep their named agent.
- **Hand off** (`SessionHandOff`; also in the title menu, `SessionTitleMenu`). "Hand off to..." lists the agents. Handing off ends the session as Done with "Handed off to Codex" and starts a new session in the same experiment on the same branch. The new session opens with a summary card written from the conversation and `history`, and a card linking back to the session that ended. Skill packs, evaluations and connectors work with every agent.
- Working (`SessionWorking`, `SessionStart`): a person can type to steer, and can @-mention a session of the experiment to send it a message ("@Codex focus on database queries"). Without a mention the text goes to the session being viewed. While the agent works the send button is a stop button (a filled square in a circle, labelled "Interrupt"), exactly as Claude Code swaps them: it stops the agent's current step. With text in the box send shows instead, and the text is delivered before the next step. "Stop session" in the header ends the session. The agent reads steering as chat; it can change what it tries and never what counts.
- Waiting for you: the composer stays open for an answer ("Answer, or approve the card above"), and the card that waits is above it.
- **Keep going?** (`SessionKeepGoing`). When the sealed patience number of trials in a row across all sessions are not Kept, the experiment is Waiting for you with this card: "The last 6 trials did not beat 1,102 ms. $48 of $100 is left." It lists what was tried (agent, hypothesis, outcome; "Copy as a note" copies the list) and the patience figure, with "Keep going" and "Stop here". Settings, Approvals can set it to Allow (never pause) or Always ask. It is the seventh card kind.
- **Continue on another agent?** (`SessionFailover`). When an agent platform is unavailable or rate-limited the session is Waiting for you with this card. It names the agent Auto would choose and why, what the new session starts with, and the policy, with "Continue on Gemini" (the named agent), "Choose another agent" and "Wait and try again". Policy may allow it without asking. A timeline line records it. It is the eighth card kind.
- **Cost on the cards.** Every trial card shows its cost ("$5.20", or "$1.70 so far" while measuring): the agent's spend since the previous trial of the session plus the judge time for the measurement. A trial that stopped at the quick check carries the tag "Quick check", its lower cost, "Stopped after 1 repeat" and "Guardrails not checked" (the quick check never decides Kept). The scoreboard strip adds "$14.00 per kept trial" (spend divided by kept trials; absent while nothing is kept). The Seal experiment card draws a "Cost and value" group, open, with the value model, the expected return, the budget, the quick check, patience and the cost estimate ("One measurement costs about $0.30 (3 repeats on Sales history v7). This budget buys about 12 trials."). The Win card says "Worth $7,488 a year" with the value model named and "The win cost $42, including the 11 trials that were not kept."; the Regression card adds "At risk: $2,088 a year" and Delivered drops by that amount until a fix is Kept and merged.
- **Value on the Seal card.** The card shows the project's value model for the metric with its source and who set it, the expected return line ("Goal: 14.0%, worth about $11,000 a year. Budget $10.") and "Propose a different value", which needs a project owner's approval on the same card. With no value model the card says "No value set" and the experiment's wins show the metric only. An agent never sets or edits a value model.
- **Context.** The Details panel's Context section shows the share used and has "Compact" (summarise and continue) and "Fresh session with summary". Ratchet compacts on its own at 80% and says so in a timeline line ("Compacted the conversation automatically at 80% of the context window. 44% used now.").
- Done and Failed: "Continue this session" starts a new sandbox from the session's branches. Failed also offers "Start again" in the failure line.
- Read-only (`SessionReadOnly`): a viewer reads. The box is greyed, no button is active, and it says "Viewers read experiments. Only editors and owners can send."

### Session header and panels

The session header is one slim bar the full width of the main area, like Claude Code's desktop header (`SessionWorking` and the boards after it).

- **Left.** The breadcrumb "Project / Experiment title", the experiment title in bold (a spawned session adds a third part, "Project / Experiment title / Codex session"). Next to it a chevron button opens the **title menu**: Rename, Pin or Unpin, Experiment details, Copy link, Stop session (danger), Archive. Stop session still confirms inline, in the chat, with "Stop session" and "Keep working". The state and activity pill follows the title.
- **Right.** Icon toggles in this order, then a separator, then More and Share: Details, Trials, Changes, Terminal, Preview, Files. Each is an icon button with `aria-pressed`, an `aria-label` and a `title` that names it with its shortcut ("Terminal (⌘⇧T)"). More holds Export conversation, Keyboard shortcuts and Report a problem. Share is a button with an icon and the word.
- **One panel at a time.** A toggle opens its panel beside the chat; pressing the pressed toggle, or the close button in the panel's header, closes it. Opening another toggle swaps the panel. The panel is about 440px wide, resizable by a drag handle on its left edge (a separator that also takes the arrow keys), and has its own header naming the panel. The chat column narrows; the scoreboard strip stays under the bar inside the chat column and tightens to fit. Details is open by default on wide screens; the other boards draw every panel closed unless the board is about that panel.
- **Details.** Sections with a small label, then rows (icon, value, a trailing action): Experiment (state, version, "Experiment details"), Environment (with a settings icon that starts the Change environment card), Repos (each repo with its branch under it; "+" posts an Attach repo card in the chat, because settings are tools), Agent (agent, plan and platform), Budget (the figure, the bar, "Change budget"), Sessions (status icon, name, spend; each links to that session) and Context (percent used, tokens used of the window).
- **Trials.** The scoreboard and every trial across sessions, newest first, filtered by session. Each row shows the trial number, title, outcome tag, the agent, the judge's value, what it started from and the change. A row opens its trial card, or the receipt for a Kept trial.
- **Changes.** The diff of this session's branch per repo against its base. A picker chooses what to compare: "Trial 12, Kept" by default, or "Working copy". The files are listed on top, grouped by repo with +/- counts, the unified diff of the selected file below. A path the sealed experiment protects is marked with a lock and "Protected: a change here is Rejected". The server stores no diff: the panel fetches it from the platform when opened (see [session model](../session/model.md)).
- **Terminal.** A shell in this session's sandbox on its platform. An editor or owner can type; a viewer sees the output read-only, with a line saying so. The header line names the sandbox ("Agent sandbox · Claude Managed Agents") and a note says "The judge never runs here. Measurements happen in a fresh judge sandbox." Opening it is recorded in the audit log.
- **Preview.** A browser on a port of the sandbox, with an address bar, reload and open in a new tab. The Preview button exists only when the environment exposes a port; otherwise it is absent, not disabled.
- **Files.** The file tree of the attached repos in the sandbox, the repo as the top level; the open file is shown read-only with a path bar.
- **Share.** A popover: people in the project with their role, each marked as inherited from the project, a switch for "Anyone in the organization with the link can view", and Copy link. Sharing never grants more than a person's role in the project. A viewer sees only Copy link.
- **Read-only.** A viewer can open every panel. In Terminal they cannot type, in the title menu Rename, Pin, Stop session and Archive are disabled, and the header carries the one-line reason (`SessionReadOnly`).
- **Keyboard.** Each toggle has a shortcut shown in its tooltip: ⌘⇧D Details, ⌘⇧R Trials, ⌘⇧G Changes, ⌘⇧T Terminal, ⌘⇧P Preview, ⌘⇧F Files.

### Home and New experiment

New experiment is a composer on the home page, not a dialog and not a form. Home (`Home`) shows the composer (above) under the title "What do you want to improve?". Sending starts an experiment with its lead session, Not sealed until a person seals it from the Seal experiment card; it may stay Not sealed and end there. Nothing else is asked before the first message. Below the box:

- **Waiting for you.** The experiments that need a person, a ListPage section: each row has the title, the card it waits on ("Raise budget") and its age; it opens the experiment with the card in view. Empty: the section is absent, not an empty box.
- **Ideas** under the box: the top three across the person's projects (Ratchet suggests, a person starts), each with the experiment, its project and metric, the expected value a year with the improvement it assumes, the expected cost and the ratio ("95×"), sorted by the ratio. "Start" opens the composer filled in. With none there are no Ideas: never a canned feature tour.

With no experiments at all (`HomeEmpty`) the page is the composer alone and the sidebar is `SidebarEmpty`, with the Projects and Customize rows still there. A sidebar row's activity icon updates live.

When an experiment is sealed and the budget allows, nothing asks anything: a person types "cut checkout p95" and the agent starts.

### Projects

A project groups the experiments for one area of the code. Every experiment belongs to exactly one project, and New experiment asks for it with the Project chip.

**Projects** (`Projects`, a ListPage, reached from the sidebar row). All the projects the person can see, as rows or cards: the name, a one-line description, the person's role in it (Owner, Editor, Viewer), its experiments, its wins and its spend this month. The primary action is "New project". Delivered, Pending, Spent and Return sit in a strip at the top (Spent reads "includes $X on experiments with no win", and Return is Delivered over all spend in scope), with a "Report" action beside "New project" that opens `Report`, and the page is the way to see everything: a win counts as Delivered once its pull request is merged, and Pending, while a pull request is open, is not in Return. The strip is shown only for experiments that state a value per unit, and is absent, not zero, otherwise. Empty: "No projects yet." with "New project". There is no board for it: a brand-new organization sees `HomeEmpty`. A person who is not an organization owner sees only the projects they belong to.

**Project page** (`Project`, a DetailPage). Back to Projects. The title, the person's role, counts (experiments, wins), the description and "New experiment" (which opens the composer with this project chosen). Sections of rows and quiet tables:

- Experiments: a table with the experiment, baseline to best, state, activity, and budget and spend. A row opens the experiment. Empty (`ProjectEmpty`): "No experiments in this project yet." with "New experiment".
- Ideas (`Project`): possible experiments Ratchet suggests from the repos, connectors and past experiments, ranked by the ratio of expected value (from the project's value models) to expected cost (from similar experiments). Columns: the idea, metric, expected value, expected cost, ratio, "Start", which opens the composer filled in. An idea on a metric with no value model shows "No value set" and sorts last. Ratchet proposes; a person starts. Home shows the top three across projects under the composer.
- Value (`Project`, `AddValueModel`): value models per metric, with the source, who set it and how many experiments use it. A project owner sets one value model per metric with "Add value model" (a dialog: metric, one unit, dollars a year, source, optional link). A metric without one shows "No value set" and its wins count in no dollar figure. Agents never set or edit a value model.
- Connectors used: the connectors this project's experiments read, with their status; a name opens `ConnectorDetail`.
- Budget: spent this month of the project's optional monthly cap, and the default budget per experiment (falling back to the organization's). Project owners change both. Neither can pass the organization's cap.
- Members: a quiet table of members with their role in this project. A role set for this project is marked; otherwise it shows the organization role as the default. Project owners add and remove members and set a role for the project. A project always keeps at least one owner.

A viewer sees the same page with its controls disabled and a one-line reason ("Only project owners can change this. You can read it.").

### Customize

A sidebar page with tabs **Evaluations, Skills, Connectors, Agents and Plugins**. Each tab is a ListPage with a **Yours** and a **Discover** toggle (both are links, so each is a URL). Yours lists what the organization has. Discover lists what can be added: for connectors the grid of systems with their logos (Snowflake, Databricks, BigQuery, Postgres, DynamoDB, Amazon S3, an MCP server); for the others the templates and packs Ratchet offers. Discover keeps no "Featured" banner and no "For you" marketing beyond what reads as a plain list. A row or card opens the one shared **DetailPage** layout, and a new kind of item gets no page style of its own. The primary action of each tab is "Add evaluation", "Add skill", "Add connector", "Add agent" or "Add plugin". Customize is a library of reusable things. Setting one up in a chat with a card still works, and what a card adds appears here. Owners and editors add and change items; a viewer reads, with controls disabled and a one-line reason.

- **Evaluations** (`Evaluations`, `EvaluationsEmpty`, `EvaluationsDiscover`, `EvaluationDetail`, `AddEvaluation`). Reusable evaluation templates. A row shows the name, the kind (Speed, Quality, Size or Cost), the direction and "used in N experiments". The detail page shows the command, the direction, the guardrails, the standard planted cheats for the kind and the environment, and the experiments that started from it. A sealed experiment starts from a copy, so editing a template never changes one. The seal checks (baseline, noise, cheats) are the judge's and run when an experiment is sealed. Empty: "No evaluations yet."
- **Skills** (`Skills`, `SkillsEmpty`, `SkillsDiscover`, `SkillDetail`, `AddSkill`). Versioned skill packs, written know-how that agents read. A row shows the name, the latest version and "used in N experiments". The detail page shows its versions, who may read it (agents only), the experiments that read each version, and the line "The judge never reads a skill pack. It never holds holdout data." A project can turn a skill On or Off for its experiments. Empty: "No skills yet."
- **Connectors** (`Connectors`, `ConnectorsEmpty`, `ConnectorsDiscover`, `ConnectorDetail`, `AddConnector`, `AddConnectorMcp`, `ConnectorError`, `DatasetHoldout`). The data systems and MCP servers an agent's code may read. A cloud account is not a connector, and the code host is not one either: repos stay under Settings, Connections.
  - **List** (`Connectors`): a quiet table. Each row has the logo, the name and target ("Snowflake · ANALYTICS"), a one-line meaning, the status (Connected, Reconnect, Not checked) with word and icon, last checked, and "used by N experiments". Empty (`ConnectorsEmpty`): "No connectors yet." and "Add connector".
  - **Discover** (`ConnectorsDiscover`): the grid of connectors and their logos, reached from "Add connector" and from the Add credential card.
  - **Detail** (`ConnectorDetail`): a panel "How access is scoped": credentials are registered once and kept in the platform's credential store, and Ratchet keeps none; agents get a read-only credential on the views listed, holdout excluded; the judge gets its own read-only credential that also covers the holdout, kept on the judge platform; both are short-lived and minted per session. Then a **Datasets** table: name, version, size, marking, Agents ("Can read" or "No access") and Judge ("Can read"). The holdout row is marked "Restricted to the judge" and has no grant control. Row actions on the connector: Check connection, Update credential, Remove. A dataset's name opens `DatasetHoldout` for a holdout, or its own page for another.
  - **Add** (`AddConnector` for Snowflake, `AddConnectorMcp` for an MCP server): the per-system fields, then two credentials with a short recipe each ("Create it in Snowflake first: a read-only role on the views you list, holdout tables not granted"; "Judge credential: a separate read-only role that also covers the holdout"), a "What each one gets" block, and secure fields whose values go straight to the platform's credential store.
  - **Error** (`ConnectorError`): "Can't read the credential for orders-db." with what to do, "Check again" and "Update credential". Its datasets show "Not checked", never empty, and the page names the experiments that cannot measure until then.
  - **Holdout dataset** (`DatasetHoldout`): one holdout dataset under its connector, with its versions by date (v4 today, v3 three weeks ago, v2 last month), a version never changing, the line "Marked Holdout. Enforced by the credentials: only the judge's includes it.", and the experiments that use it.
- **Agents** (`Agents`, `AgentsEmpty`, `AgentsDiscover`, `AgentDetail`, `AddAgent`). A quiet table of agents. Columns: the agent with its logo, platform, model, parallel limit, used in N experiments, last used. A row opens `AgentDetail`: platform, account, model, parallel limit, "What the agent holds" (a short-lived git token for its own branch per repo; read-only connector credentials that leave out the holdout; no model key) and its recent trials. There is no agent order, no Pause agent and no per-agent budget share. Platform accounts stay in Settings, Agent platforms, which links here. Self-hosted, owners manage agents and others read; on Ratchet cloud the list is read-only. Empty: "No agent is added yet." **Agent scoreboard**: the Agents tab (Yours) is the agent scoreboard. Per agent: experiments, trials, kept, wins delivered, cost per win, median time to a win and Delivered, from the judge's measurements in this organization, filtered by evaluation kind, project and range, with the note "Measured by the judge on your code. Not a vendor benchmark." Each row shows the cost tier ("$" to "$$$") with the measured figure ("about $2.40 per trial here"), and a switch for whether Auto may use the agent. A control sets the organization's default agent, which Auto uses until there is data; no agent is pre-selected by brand. `AgentDetail` shows the same figures per evaluation kind.
- **Plugins** (`Plugins`, `PluginsEmpty`, `PluginsDiscover`, `PluginDetail`, `AddPlugin`). A plugin is a bundle that adds evaluations, skill packs, suggested connectors and recommended agents, each under its own kind. Its detail page lists what it adds, grouped by kind, and each item links to its own page. A plugin has no powers of its own: it can never mark, unmark or grant access to a dataset, and its detail page says so. Removing a plugin asks, in a small dialog, whether to keep its items; an item in use by an experiment is never removed, and the dialog names those. Empty: "No plugins installed."

The holdout rule holds on every Customize page: a skill, a plugin or a connector never changes it.

### Experiments

**Experiment page cost and value** (`ExperimentDetail`): the strip adds "Per kept trial" (spend over kept trials); the sealed definition lists "Quick check", "Patience" and "Value model"; a "Value" section shows the sealed value model, the experiment's worth, its Return and a note on how At risk works (while Watch finds a regression, the regressed amount moves from Delivered to At risk until a fix is Kept and merged); "Where the spend went" shows Kept trials, Within noise, Worse, Guardrail failed, Rejected, Failed and Not measured as a stacked bar to scale and a table of dollars and shares; each trial row shows its cost, and a trial that stopped at the quick check is marked "Quick check". Settings, Budgets shows the same breakdown across the organization and "Cost per win by project". The receipt's Experiment group adds the value model with its source and who set it, "Worth of this win", "Cost of the win" and "Return of the win".

**Report** (`Report`, reached from "Report" on Projects): the monthly report for the organization or, with the project picker, one project. Strip Spent, Delivered, Pending, At risk, Return; then "Where the spend went", "Agent scoreboard" for the month, "Top wins" with "View receipt" links, and "Experiments stopped with no win". Actions "Export PDF", "Export CSV" and "Email this monthly" (to chosen members). Owners and editors read it; a project's viewers read that project's.

There is no experiments list page and no "All experiments" link. Projects shows everything: its strip carries Delivered, Pending and Return across the experiments that state a value per unit (there is no dashboard page), and each Project page lists that project's experiments. A win counts as Delivered once its pull request is merged, and Pending, while a pull request is open, is not in Return. A sealed experiment is never edited; "New version" is on its detail page. Global search keeps an Experiments scope.

**Experiment detail page** (`ExperimentDetail`, a DetailPage), opened from "Details" in the experiment page's header. Back to its project. A title with its state and version. Sections of rows and quiet tables:

- Definition: Metric and direction, Evaluation command, Protected paths per repo, Guardrails, Repeats, Acceptance criteria in one sentence. Immutable: "Sealed experiments never change. A change makes a new version, and numbers do not carry across versions."
- Seal checks: the baseline, the noise check, the cheat checks, as they were when sealed.
- Data: the evaluation data and the holdout, each named with its dataset version ("orders v4"), its connector and its marking; the holdout marked "Restricted to the judge". A name opens the dataset page. Below them the skill pack versions the agents read ("Postgres query tuning v3"), each linking to its Customize page, and the evaluation template the experiment started from.
- Scoreboard: the chart of every trial across all its sessions, with one line per session, and the numbers.
- Budget: spent of budget, and a control to change it (editors and owners of the project). The line says whose cap it sits inside: "Inside the Checkout platform cap of $2,000 a month".
- Sessions: a quiet table of the experiment's sessions: the session (named by its agent, with its logo), platform, started, ended, spend, state (Working, Done, Failed) and clean-up (Removed, Not removed). When a session is not removed a banner sits above the table: "The Gemini session was not removed. Ratchet retries, and its cost counts until it is gone." A session still working shows "Not ended" under Ended, never an empty cell.
- Trials: a table of every trial across all its sessions, with hypothesis, outcome, value, session (named by its agent) and what it started from. Failures are included. A row opens that session's chat at that trial.
- Wins and their pull requests, each linking to its receipt.
- Watch: the switch and its trigger (on a schedule, when the default branch moves), and the last measurement.
- Versions: each version with its seal date; numbers are never compared across them.
- Delivered, Pending and Return appear here only when the experiment states a value per unit.

**Receipt** (`Receipt`, a DetailPage). One win: the experiment version and seal, the commits per repo, the values, repeats and noise, the number of trials tried, the holdout result (Passed or Failed, never a value), the second opinion with its notes, what was spent, and "Signed by the judge" with "Verify again", which checks "The signature matches", "The signer is the judge" and the image digest. Two lineage groups sit beside the numbers. **Data**: the dataset versions read, the commits per repo, and the credentials used with their scope (agents read-only with the holdout excluded, the judge its own). **Compute**: the judge platform and environment, the judge image and its digest, and the agents and sessions with their platforms. Below it the lineage: what each trial started from, as a chain from the baseline to the win, each node a link to its trial.

### Global search

A centred palette over the app, opened from the sidebar's Search row (a link to `SearchStart`), Cmd/Ctrl+K or "/". The field is focused. Scopes, left to right: All, Projects, Experiments, Sessions, Trials, Datasets, Customize, People; Left and Right change scope.

- **No query** (`SearchStart`): Needs attention (what waits for you, such as a Seal experiment card, and a connector that needs reconnecting), Recents (the last experiments and connectors you opened) and Actions (New experiment, New project, Add connector, Open Settings). Typing replaces it with results (`Search`).
- **With a query** (`Search`): results grouped by kind in scope order, the match highlighted. A project shows its counts; an experiment its state and baseline to best; a session its state, agent and repos; a trial its number, outcome (Kept) and experiment; a dataset its connector and, for a holdout, "Restricted to the judge"; Customize rows say what they are (Evaluation, Skill pack) and the group has "Show all N". Each result opens the exact place: a project its page, an experiment its page, a session its chat inside the experiment, a trial its receipt or its place in the session, a dataset its page, an evaluation or skill pack its Customize page. No match is `SearchEmpty`.
- **Footer keys**, only keys that work: Close Esc, Move Up and Down, Change scope Left and Right, Actions Option+Enter (a result's menu, shown only where a result has one), Open Enter. The no-query and no-match boards omit Actions because no row has a menu there.

### Settings

Settings is a dialog, not a page. It opens from the user menu or a Settings result or action in search. It is a large centred dialog with a left rail (`SettingsRail`) and a search field. The first Esc clears the rail search. The rail is grouped by whose setting it is, with a hairline between groups: **You** (Profile, Appearance, Access tokens, This device) and **Organization** (General, Members, Single sign-on, Agent platforms, Approvals, Budgets, Connections, Audit log). It reopens on the section you used last. The rail search filters sections and rows by title, description and keywords, and opens the first section that matches.

Settings are for reading and revoking what was approved. They are not where setup begins. Two things are still set up here, because no experiment can start without them: agent platforms (self-hosted) and members and sign-in. Connectors, agents, evaluations, skills and plugins are set up once in Customize, not here, so that a credential is made once and used by every experiment; a chat can also start one from a card.

What each section shows:

- **Profile** (`SettingsProfile`): name, email, sign-in provider, role. **Appearance** (`SettingsAppearance`): theme, light, dark or system. **Access tokens** (`SettingsTokens`, `SettingsTokensEmpty`): a quiet table of your tokens with scope and last used, Create access token, Revoke; a new token is shown once. **This device** (`SettingsDevice`): Install app, notifications for this device, the server address; installed web app only where it applies.
- **General** (`SettingsGeneral`): the organization name, the deployment (Ratchet cloud or Self-hosted) and the server address.
- **Members** (`SettingsMembers`): users and service principals as a quiet table with their organization role (Owner, Editor, Viewer), which is their default in every project, the projects they belong to, and status; invite, change role, remove. An organization always keeps at least one owner. A project's own roles are on the project page.
- **Single sign-on** (`SettingsSso`): OpenID Connect and GitHub, each with its status and the domains it admits. No passwords.
- **Agent platforms** (`SettingsPlatforms`, `SettingsPlatformsEmpty`, `SettingsPlatformsManaged`, `AddPlatform`, `PlatformError`): a quiet table of Claude Managed Agents, AWS AgentCore, the OpenAI Agents API, Microsoft Foundry Agent Service and Google Agent Runtime: the account, the agents on it, a status (Connected, Needs attention when its credential is rejected), and one platform badged "Judge platform". Row actions are Test connection, Update credential and Remove; an "Add platform" button adds one. Environments and connector credentials are listed under Connections, not here, and a line links to Customize, Agents for the agents on these platforms. Self-hosted, owners manage all of it and others see it read-only. On Ratchet cloud the section is read-only for everyone (`SettingsPlatformsManaged`): Ratchet manages the platform accounts and bills at cost through each experiment's budget, and the section shows data and retention per platform (for example "United States only, no zero data retention"). A rejected credential is `PlatformError`: the row says Needs attention and what to do.
- **Approvals** (`SettingsApprovals`): one row per card kind with its policy: Always ask, Allow up to a limit, or Allow. Defaults: Seal experiment asks; Raise budget asks above the limit set here; Attach repo asks; Change environment asks; Open pull request asks. Add credential always asks and shows no choice: a person must type the value. Which role may approve which card is read here.
- **Budgets** (`SettingsBudgets`): the organization's default budget per experiment (the figure the composer's budget starts from when a project sets none; the boards show $10 as the example), the monthly cap and spent this month, and a quiet table of projects (with their cap and spend) and experiments with their budgets and spend, and spend by experiment and by session. No budget can pass its project's cap, and none the monthly cap. Organization owners change the default and the cap; project owners change the project's cap and default on the project page; editors change a single experiment's budget from the experiment.
- **Connections** (`SettingsConnections`): what was approved in chats, in three groups: Repos, Credentials (names and where each is kept, never values) and Environments. Each row says who added it, when and how many experiments use it, and has Revoke. Connector credentials are read-only and kept in the platform's credential store; a line links to Customize, Connectors for data systems.
- **Audit log** (`SettingsAudit`): the tool calls that changed something and the approvals: who, what, when, the outcome, as a quiet table with a filter. Never empty: signing in is the first entry.

Read-only is `SettingsReadOnly`.

- **A setting is a row.** The title with a one-line muted description under it on the left, the control on the right (switch, select, segmented control, field, button), and a hairline between rows. A sub-setting is indented under its parent and is disabled while the parent is off. A section can have several headed groups. A list inside Settings (members, access tokens, connections, audit log) is a quiet table: column headers, an icon or avatar and name with a muted second line, a tag for a kind, an icon and word for a status. No cards inside cards.
- **Organization settings are read-only for non-owners, not hidden.** Owners change them. Editors and viewers see the same section with its controls disabled, a one-line explanation ("Only owners can change this. You can read it.") and a lock beside the section in the rail. Revoking a connection is an owner action.
- **Narrow screens.** Below 720px the dialog is full-screen and the rail becomes a search field with a select of sections.

### Reuse the patterns

One detail-page layout, one popover, one palette and one dialog. A new kind of thing uses them; it does not get its own page style. Menus and popovers close on an outside click. Every menu item is a `.mi`, every select uses the `.selw` wrapper, and every control has a disabled style. A new card kind reuses the card frame: title, what would happen, what it may cost, two buttons.

## Rules for every page

- **One set of page states.** Every page uses the same six: loading, empty, failed, refused, partial, not checked. Each says what happened and what to do, in a sentence. Failure is never drawn as empty or zero, and something not checked is never drawn as healthy.
- **The holdout is marked.** A holdout always shows as "Restricted to the judge". An agent never holds the holdout credential and never sees a holdout value, only the outcome ("Kept", "Failed holdout"). No control grants it to an agent: the control is absent, not disabled. The copy says it is enforced by the credentials: an agent's credential leaves it out and only the judge sandbox's includes it. In a Datasets table its row reads "Restricted to the judge" with no grant control at all. A dataset version never changes, so a version named on a receipt is the one read. Chat never changes it. (target: experiments are not built yet.) It has its own board (`DatasetHoldout`), because the screen looks different.
- **Setup happens in the chat, as a card.** Nobody visits a settings page before the first message. A person states a goal; when the agent needs a repo, a credential, an environment, a budget or a seal, a card appears at that moment.
- **A card shows what would happen and what it may cost before Approve.** Confirm after the preview, never before. Nothing is created or spent until a person decides. A destructive step such as Stop session confirms inline.
- **Nothing is asked when policy already allows it.** A pre-approved card collapses at once to "Allowed by policy". Add credential is never pre-approved.
- **Only the judge's numbers are shown as results.** A number made in a session is never drawn as a result.
- **A control says exactly what it does.** "Seal experiment", not "Approve"; "Stop session", not "OK". A control that does nothing is deleted. A footer or menu lists only keys and actions that work.
- **Same in every client.** If the web app, the macOS app, the CLI and MCP disagree about state or words, one is wrong.
- **Status is never colour alone.** Every status and outcome has a word. An activity has its own icon shape: Working, Waiting for you, Done, Failed. An experiment state has its own icon: Not sealed, Sealed, Watching, Regressed. A trial outcome is a word in a tag: Measuring, Kept, Within noise, Worse, Guardrail failed, Failed holdout, Rejected, Failed.

### Empty states

One sentence and at most one action, no feature explanation. A list gets its own board only because the screen looks different. The sidebar is `SidebarEmpty` only when the organization has no experiment. A count that is zero stays on screen (spend `$0`, `0 kept`), never hidden.

| Screen | Empty when | Sentence | The one action | Board |
| --- | --- | --- | --- | --- |
| Home | no experiment in the organization | No experiments yet. | none; the composer is the action | `HomeEmpty` |
| Sidebar | no experiment | Experiments you start appear here. | none | `SidebarEmpty` |
| Search | no match | No results for “query”. | none | `SearchEmpty` |
| Settings, Access tokens | you made none | No access tokens yet. | Create access token (row above) | `SettingsTokensEmpty` |
| Settings, Agent platforms | self-hosted, none added | No agent platform is added yet. | Add platform | `SettingsPlatformsEmpty` |

| Customize, Skills | none added | No skills yet. | Add skill | `SkillsEmpty` |

Never empty, so no board: Members (you are in it, and one owner always remains), Audit log (signing in is the first entry), Approvals, Budgets, General, Profile, Appearance and Single sign-on (settings rows, not lists), an experiment (it starts with the composer). Connections is empty until the first card is approved: its row reads "Nothing approved yet." and has no action, and it shares `SettingsConnections` rather than its own board. A connector whose datasets cannot be read shows them as "Not checked" (`ConnectorError`), never as an empty table. An experiment with no sessions cannot exist: it starts with its lead session. An experiment with no trials or no wins says "No trials yet." or "No wins yet." inside its section, with no board.

## Colour and type

Midnight Brass. The values are in `design/tokens.toml`; these are the rules.

- Brass is the brand and the only accent. People do not choose a colour.
- Text meets 4.5:1 in both modes. A control's outline meets 3:1, so a control uses `line2`, not the `line` divider.
- Status is never colour alone: a word or a shape comes with it.
- Light and dark are both designed. A change is checked in both, and a board is drawn light, its dark twin generated.
- The areas keep one colour each in diagrams and navigation: the judge is brass, experiments and sessions are blue, the organization is slate (target; slate is not a token until it is added to `tokens.toml` with a contrast check). Green is the success state only (Kept, Done, Connected), never an area. Never use these colours for anything else, and never rely on colour alone to say which area a thing belongs to.
- Tokens are named by meaning (`canvas`, `raised`, `line2`, `ink`, `accent`), and light mode redefines the same names. Never write a raw colour, radius, size or duration in a screen or a board. Type comes from the type classes, never an inline size.

## Clients

The web app and the macOS app (target) share behaviour, words and element ids, never pixels. The clients are the web app, the web app installed on Windows and Linux, the `ratchet` CLI and `ratchet mcp`. `ratchet "cut checkout p95"` starts the same experiment in the terminal (target). The CLI and MCP print the same words and the same cards, as text. If any two disagree about state or words, one is wrong.

The macOS app is SwiftUI, and macOS only; on Windows and Linux the web app installed as a progressive web app is the desktop app. The Mac app stays ruled in, but its boards are removed for now and are owed once the web direction is approved. When they return, its window chrome, menu bar item, native Settings window, native notifications and offline banner follow the same behaviour as this page. The Mac is only a client of the server's API. It runs no agents and no sandboxes.

What the installed web app adds, on Windows and Linux (`WebInstalled`, `WebNotification`, `WebOffline`):

- Its own window and taskbar icon; the page is the same, with no browser toolbar.
- Install is offered once, quietly: a row in Settings, This device ("Install app"), and the browser's own prompt. Never a banner over work. On macOS the row says "Get the Mac app" instead.
- A badge on the icon: the count of experiments that are Waiting for you.
- Push notifications for what needs attention (a win, Waiting for you, a regression, a budget spent), asked for at the moment it helps (after the first message: "Notify me when this needs me"), never on first load. Turned off in Settings, This device.
- An offline screen when the server cannot be reached: what was last known, marked as not current, and Try again. Nothing is cached beyond the app itself.

## Accessibility

Targets, labels and focus are checked on the boards in both light and dark. Every control is reachable by keyboard, the focus ring uses a token, and every icon-only control has a label. A streaming message is announced when it ends, not word by word; a card that needs a person is announced when it appears.
