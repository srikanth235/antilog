# An API endpoint

The OpenAPI document is generated from the Rust types in `antilog-server` and is the one description of the wire format. The web client, the CLI and the schema tests all read it. Never edit it by hand. Built: the document is generated by `cargo run -q -p antilog-server -- openapi`, with the routes of `api/auth.rs`, `api/organization.rs`, `api/session.rs`, `api/customize.rs`, `api/model_key.rs` and `api/live.rs` merged in `api.rs`. The `/runner/*` routes and `/mcp/sessions/{id}` are not in the public document.

## Steps

1. **Decide the product call first.** An endpoint that exposes a new thing is a product change; see [product](../product/SKILL.md). An endpoint never returns data from a customer's systems: the server stores only ids, versions, numbers, states, the conversation's words and audit rows.
2. **Write the types.** Request and response types live in `crates/antilog-types/src/` and derive their schema with utoipa. Follow [stack/rust/antilog.md](../stack/rust/antilog.md).
3. **Write the handler.** `crates/antilog-server/src/api.rs`, with `#[utoipa::path]`. The handler is thin: it decodes, calls the action layer (a write, see [write-action.md](write-action.md)) or one read function, and encodes the answer. It tests no role and writes no audit row.
4. **Regenerate the document.** `cargo run -q -p antilog-server -- openapi > openapi/antilog.json` writes the committed document; a test in `antilog-server` and CI fail when it differs. List a new handler under `paths(...)` in `ApiDoc` (`crates/antilog-server/src/api.rs`).
5. **Regenerate the TypeScript client.** `pnpm generate:api` in `web/` writes `web/src/api/schema.d.ts` with `openapi-typescript` (`openapi-fetch` joins when the web app lands, see [stack/libraries.md](../stack/libraries.md)). Never edit the output. See [stack/typescript/antilog.md](../stack/typescript/antilog.md).
6. **No CLI command.** The CLI is `antilog runner` only; an endpoint is driven over HTTP (see [../antilog/SKILL.md](../antilog/SKILL.md)).
7. **Setup tool.** If an agent needs it, it is a tool served on the session's MCP endpoint, not only an endpoint: see [tool.md](tool.md).
8. **The macOS app.** If the Mac app shows it, it reads the same document (see [stack/swift/antilog.md](../stack/swift/antilog.md)).
9. **Tests.** A schema test that every route in the document has a case and its answer parses into its type; insta snapshots of the document and of the event union; a test that the route is refused without a token and as a role the matrix denies. See [../land/tests.md](../land/tests.md).
10. **Docs.** Fix the wire conventions below if one changed, the CLI help text and the glossary if a word is new.

## Wire conventions (target)

Keep these unless the owner rules otherwise.

- Property names are camelCase. Ids are strings. Times are epoch milliseconds unless a field says otherwise.
- Nullable response fields are required and carry `null`. Inputs and query structs stay optional.
- Errors are `{ "code", "message", "fields" }` with the usual statuses.
- Live updates are server-sent events (see [live-event.md](live-event.md)).
- Every route needs a signed-in member or an access token, and every route is permission-checked.
- No response, event or error carries a secret or customer data (see [product promises](../product/promises.md)).
