# Judge: rules that never bend

- Count only the judge's numbers, because a number made in an agent's session is not a trusted measurement. It is never shown as a result.
- Never give an agent the holdout credential, because an agent that sees the held-back data will fit it. Only the judge sandbox holds it.
- Never change a sealed experiment, because a definition that can move is not a benchmark. A new version starts a new record, and numbers never carry across versions.
- Never let a person or an agent mark a win, because a rule a person can override is not a ratchet. Only the acceptance criteria can, and they are one pure function in code.
- Let chat change what an agent tries and never what counts, because the words in a conversation are not evidence.
- Take protected files from the seal for every trial, never from the trial, because a trial that carries its own evaluation grades itself.
- Let an agent read the evaluation's code and never change it, because reading helps it iterate and changing it changes the score.
- Never change an outcome once written, because an outcome that can move is not evidence. A new finding is a new measurement.
- Never change a dataset version after it is created, because a measurement that names a version must be reproducible. New data is a new version.
- Keep the judge credential read-only, cap holdout checks per experiment version (sealed, default 20), and show the holdout to the trial's code at the same path and shape as the evaluation data, because Failed holdout is one bit per trial and an agent that can probe it, or tell the holdout apart, can fit it.
- Never put a holdout value in history, a message, a trial result or a receipt an agent reads. The holdout appears only as Passed or Failed.
- Never let the judge read a skill pack or a plugin, because advice to agents must not reach what counts. A plugin never marks, unmarks or grants a dataset, and a skill pack never holds holdout data.
- Start a sealed experiment from an evaluation template by copying it, never by reference, because a template that can be edited must not move a sealed definition.
- Pin the experiment version, the seal and the dataset versions on every measurement, and name them on the receipt, with the skill pack versions the agents read, because a result nobody can reproduce is not a result.
- Refuse `measure` when the budget is spent, and let the session layer meter it, because the experiment's owner knows what a win is worth and the budget knows what was spent.
- Let the quick check run only in the judge, and never let it decide Kept, because a cheap partial number may stop a trial early and can never promote one. Only the full measurement, the confirmation and the holdout can.
- Seal the value model, the quick check setting and patience with the experiment, because a worth that can move would make Return a number anyone can change. Never let an agent set or edit a value model: a project owner does.
- Count Return as Delivered over everything spent in its scope, including experiments with no win, because a Return that ignores the misses overstates what the money bought. Count a win as Delivered only once its pull request is merged, keep Pending out of Return, and take a regressed amount out of Delivered as At risk.
- Show a failed trial as failed, never as zero or empty, and never show an unchecked experiment as healthy, because zero reads as a real measurement.
- Never let the second opinion decide, because it flags and a person reads it.
- Say "experiment", "trial" and "Return" in every word a person reads. Retired words are listed in the glossary.
