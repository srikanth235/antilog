# Rulings

## Settled boundaries

- **Context owns the code host.** The code host (GitHub, GitLab) is a context connector. A pull request is a write-back action that an experiment requests; context performs it, as an explicit, audited action.
- **Agents are infrastructure workers.** An agent is something infrastructure runs. An experiment picks which agents and how many. The agent platform and the model are fields on the agent.
- **Infrastructure records spend; the experiment sets the cap.** The limit belongs to the goal; the meter belongs to the place work runs.
- **A benchmark belongs to the experiment.** It points at data (context) and an evaluator environment on a measuring platform (infrastructure). It is not a context or infrastructure object.
- **The earlier native Mac app was removed.** The web app is the client (target). A new native macOS app is ruled in the next section (target).
- **Sign-in is OpenID Connect, plus GitHub's OAuth.** Ratchet cloud offers GitHub (OAuth with its user API, since GitHub does not offer OpenID Connect for app sign-in), Google (OpenID Connect), and an organization's own OpenID Connect provider (single sign-on), which only an owner sets up. A self-hosted server uses the administrator's OpenID Connect provider. No passwords.

## Architecture (target)

Decided by the owner, 16 Nov. It replaces the launcher, the runner, the managed runner, the sandbox backends and the "Where work runs" setting. Everything here is target; nothing is built on this branch.

- **Two offerings.** Self-hosted: the Ratchet server is a Docker Compose service (server and Postgres) in the customer's infrastructure, and it uses the agent platform accounts the customer already has. Ratchet cloud: we host the server and manage everything, agent platform accounts included. Both are supported from day 0, and one core serves both (see Ratchet cloud below).
- **Ratchet runs no sandboxes. Agent platforms do.** An agent platform is a managed service that runs an agent's loop and its sandbox as one durable session: Claude Managed Agents, AWS AgentCore, the OpenAI Agents API, Microsoft Foundry Agent Service and Google Agent Runtime. Ratchet is agnostic to them. Every platform sits behind one trait, with one adapter each: start a session from a repo and branch with an agent definition, credentials and limits; send input; read its events; stop it and delete it. Platform words stay inside each adapter. Microsoft Foundry Agent Service and Google Agent Runtime run a container image Ratchet supplies, so on these two Ratchet supplies one agent image per agent, with the agent's own harness inside it. The platform still runs the sandbox; Ratchet still runs no sandboxes.
- **Whose platform accounts.** Ratchet cloud uses Ratchet's own account on each platform, and bills model tokens and sandbox time to the customer at cost through the run's budget and spend records. Self-hosted uses the customer's own accounts, on whichever platforms they already have, and needs at least one. This replaces the two model key sources (Ratchet-supplied and Your own key).
- **An agent is a model on a platform.** For example Claude on Claude Managed Agents, Codex on the OpenAI Agents API, Gemini or Grok on AgentCore, which runs one harness over many model providers, GitHub Copilot (Copilot SDK) on Microsoft Foundry Agent Service, and Gemini (ADK) on Google Agent Runtime. A run may mix platforms. Each agent's loop is one session on its platform.
- **Two kinds of session.** A **drafting session** is interactive: a person and one agent work out what better means for the experiment (goal, limits, what may change, benchmark, accept rule). It ends by pushing the experiment's files to its config branch, and the draft is ready to approve. A **run** starts on Approve: one autonomous session per agent, each started from that branch with its budget share, steered only by notes. This settles where chat and drafting run, which was open.
- **Measuring stays out of the agent's reach.** An agent asks for a measurement with the `measure` tool. Ratchet answers it as a tool the client provides, over the session's own event stream, so no platform has to reach the server. Ratchet then starts an evaluator sandbox on the experiment's measuring platform with the trial's commit and the evaluator's credential, runs the evaluation with no agent in it, reads the numbers and removes the sandbox. An agent's session never holds the holdout credential, the evaluation's code or a route to the evaluator. A platform that cannot run a command in a sandbox without an agent cannot be a measuring platform: AgentCore can; Claude Managed Agents, the OpenAI Agents API, Microsoft Foundry Agent Service and Google Agent Runtime are to be checked in the spike. Foundry has no sandbox that runs a command with no agent, and its Code Interpreter is a tool the agent calls, so the likely path is an evaluator image deployed as a hosted agent that runs only our measuring code and no model. Google has sandboxes that run without an agent; whether one can hold a credential the agent never sees is checked in the spike. Answering the `measure` client tool over the event stream works on Foundry (the model emits a `function_call` and the caller returns a `function_call_output` with the same call id), but a documented 10-minute expiry for tool outputs may apply, and a measurement can take longer. On Google Agent Runtime it is not documented, and bidirectional streaming is in preview with a 10-minute limit per query. Both are checked in the spike.
- **Timing is noisier on shared sandboxes.** Platform sandboxes run on shared hardware, so a timing benchmark's noise band is wider and fewer trials are kept. The accept rule handles it, and the experiment's page says so in one line.
- **Git is the hand-off.** Each session gets a short-lived git token, scoped to the repo, that may push only to its own branch. A trial is a commit on it, and the evaluator checks out that commit. Ratchet stores the commit id, never the diff.
- **The server never connects to data.** It orchestrates sessions and records: ids, versions, numbers, states, spend and audit rows. Agent and evaluator code read data through connectors inside a platform's sandbox. Transcripts and logs stay on the platform and are fetched when someone asks to see them, never stored by Ratchet.
- **The coding agent's code runs the experiment.** The agent writes code, that code runs the experiment, and it reads data through connectors itself. Only the evaluator's measurement counts (see the agent loop). There is no separate context plane that pulls or brokers data.
- **Credentials reach a session only through the platform's credential store** (the Claude Managed Agents vault, AgentCore Identity, the agent's Microsoft Entra agent identity on Foundry Agent Service, with secrets reached through a Foundry connection to Azure Key Vault; the agent's Agent Identity or service account on Google Agent Runtime, with secrets read from Secret Manager; or the platform's equivalent; the exact stores on the last two are confirmed in the spike, as Agent Identity is partly in preview), never in a prompt, a file in the repo or Ratchet's database. An agent gets read-only connector credentials that exclude the holdout, and a short-lived git token. The evaluator gets a separate credential that includes the holdout. The holdout is enforced by those credentials: a read-only role, view or policy that leaves holdout data out. Model access belongs to the platform account, so no model key enters a sandbox. Connector credentials are registered once (see Settled 16 Nov).
- **Connectors** an agent's code may use: Snowflake, Databricks, DynamoDB, BigQuery, Postgres, S3, GitHub, GitLab and any MCP server. Each says how to make a read-only, holdout-excluding credential for its system.
- **Build order.** The trait is designed against all five platforms from the start. Adapters ship in this order: Claude Managed Agents, then AWS AgentCore (which brings Gemini and Grok), then the OpenAI Agents API, then Microsoft Foundry Agent Service, then Google Agent Runtime. Before any product code, one tiny experiment runs end to end on all five to prove the trait, the `measure` tool and the evaluator sandbox.

## Ratchet cloud (target)

Decided by the owner, 15 Nov; "We manage everything" replaces "Where work runs" on 16 Nov.

- **Storage.** Self-hosted uses Postgres 18. Ratchet cloud uses one SQLite database per organization, inside one Cloudflare Durable Object per organization, pinnable to the EU, the US or FedRAMP. Both ship from day 0. Moving between them is an export and import of one neutral file format, not a database copy.
- **One core, two shells.** `ratchet-core` holds all logic and the API routes and compiles natively and to WebAssembly. Storage sits behind one trait with two implementations. `ratchet-server` is the self-hosted shell; `ratchet-cloud` is the Cloudflare shell. A small shared directory holds sign-in routing and billing, never tenant data. See [stack](../stack/SKILL.md).
- **We manage everything.** Ratchet cloud runs the server on Cloudflare and every session on Ratchet's platform accounts. An organization signs in, connects its repo and connectors, and starts; it runs no infrastructure of its own. Cloudflare Containers and the managed runner are no longer part of the design.
- **Ratchet's platform credentials** sit in Cloudflare's Secrets Store, bound to the Worker, never in an organization's database, a response or a log.
- **We are a data processor** for every Ratchet cloud organization: a data processing agreement, listed subprocessors (Cloudflare and the agent platforms in use: Anthropic, OpenAI, AWS, Microsoft, Google) and a stated retention rule. Ratchet keeps nothing after a run; each platform's own retention is stated beside it. The vendors promise only where data is stored at rest. Foundry Agent Service keeps data at rest in the geography of the chosen Azure resource; where the model processes it depends on the model deployment type (Standard and Regional stay in the geography, Data Zone stays in the US or EU zone, Global can be anywhere). Google Agent Runtime keeps data at rest in the location chosen (the US or EU multi-region, or a supported country); where it is processed is checked in the spike. Today the OpenAI Agents API offers data residency in the United States only and no zero data retention.

## The agent loop (target)

Decided by the owner, 15 Nov. It replaces the one-pass run, where each agent proposed one change and the evaluator measured it. It follows autoresearch (change, measure, keep or discard, repeat), for any measurable goal and made trustworthy.

- **Agents drive the loop. Ratchet decides what counts.** Each agent in an experiment runs its own loop in its own session on its agent platform until it stops: write a change, check it cheaply there (numbers made in an agent's session never count), ask for a measurement, read the result, build on it if Kept, and go again after reading the history. The agent decides what to try.
- **A trial is one measurement.** One change by one agent (one commit), measured in a separate evaluator sandbox. A run has many trials per agent. Each measurement runs the evaluation's repeats and reports the noise band. The evaluation may bring up what it needs inside the evaluator sandbox and removes it after.
- **What an agent sees.** Each trial's measured value and guardrail values on the evaluation data, so it can iterate. It never reads the holdout and never reads or changes the evaluation's code or the evaluator. This replaces "never let a proposer see the scoring".
- **Kept and confirmed.** A trial is Kept when it beats that agent's own best by more than the acceptance criteria require, the guardrails hold, and it is confirmed: measured again in a fresh evaluator sandbox and checked on the holdout. The agent learns the outcome ("Kept" or "Failed holdout"), never the holdout value. The accept rule stays one pure function in code.
- **Own lineage, may start from the best.** Each agent has its own lineage and best so far. It sees the experiment's best trial and its diff in the history and may start from it; the lineage records that. The run's result is the best kept trial across all agents.
- **The budget starts even and passes on what a stopped agent leaves.** Each agent starts with an even share. An agent's spend is its model tokens, its session's sandbox time and the evaluator time for its trials, and it sees its remaining share. When an agent stops early (its plateau), its unspent share is split evenly among the agents still iterating. Budget is never taken from an agent that is still iterating, and a paused agent keeps its share. Every move is recorded and shown on the lanes. Ratchet does not weight shares by early gains, because early gains are often noise and weighting would make agents harder to compare.
- **Stops.** An agent stops when its share is spent or after 8 trials with none kept; its session is ended and deleted at once. The run stops at its budget, its deadline, or after 12 trials with none kept by any agent. A person can Pause agent or Stop run.
- **People steer with notes.** A note goes to all agents, or to one with @ (for example "@Codex focus on database queries"). Each agent reads it before its next trial.

## Desktop apps and the "This machine" backend (target)

Decided by the owner, 14 Nov.

- **A native macOS app, SwiftUI, macOS only at launch.** It is a client of the server's API.
- **On Windows and Linux the desktop app is the web app, installed as a progressive web app** (decided 15 Nov). The same web client, installable from Chrome or Edge: its own window and taskbar icon, a badge for what needs attention, push notifications and an offline screen. On macOS the web app does not offer to install; it points to the Mac app. This machine stays Mac only.
- **Notifications are in the product** (decided 15 Nov, replacing "Notifications cut"): for a win, something that needs a person, or a budget hit, and for a run's end when asked. Native on the Mac, web push elsewhere, ids only. See [organization/notifications.md](../organization/notifications.md).
- **The device stores no data either.** The service worker caches the app's own files only, never API responses, diffs or logs. A push message carries ids only; the app fetches the rest when opened. A self-hosted server that cannot reach the browsers' push services sends no push, and everything else works.
- **"This machine" is deferred** (see Settled 16 Nov). With no sandbox backends, a Mac could propose only as a self-hosted environment of an agent platform.
- **Measuring never runs on the laptop.** The evaluator runs only on the measuring platform, so a Mac can never hold the holdout credential or produce a number that counts.
- **Clients share behaviour, words and element ids, never pixels.** The web app and the Mac app do not diverge on state or words; see [design behaviour](../design/behaviour.md).
- **The Mac app is a direct download, updated with Sparkle** (decided 15 Nov). It is signed with a Developer ID, notarized and not on the Mac App Store, so the App Store sandbox would never limit a local runner, should "This machine" come back (see Settled 16 Nov). It checks one signed update feed, ours, daily by default; a person can turn checks off, and a company can turn them off for its Macs and deploy releases itself through device management, which is also how air-gapped installs update. See [stack/swift/ratchet.md](../stack/swift/ratchet.md).

## The web client (target)

The owner approved a web-client direction, shown as boards in `design/mockups/`.

- **The screen is organised around experiments as sessions and one Customize page.** This replaces the four navigation groups (Experiments, Data, Compute, Admin). The three basics still own everything underneath. Area colour survives in the stepper and in the lineage columns (Experiment, Data, Compute). Behaviour is in [design behaviour](../design/behaviour.md).
- **An experiment is a session.** It opens as one thread: header, chart, conversation, trials, result. "Draft experiment" creates it at once as a Draft, and nothing is created in the customer's cloud until Approve.
- **Skills are a product concept, owned by Context.** A skill pack is versioned written know-how that agents read. The evaluator never reads it, it never holds holdout data, and the experiment records the versions read. It is not the agent guidance in this repo's `.claude/skills/`; in code and docs say "skill pack" where that could be confused.
- **A plugin has no powers of its own.** It is a bundle that adds evaluations, skills, suggested connectors and recommended agents under their own kinds. Each item is governed by its owning basic: an evaluation by optimization, a skill and a connector by context, an agent by infrastructure. Removing a plugin asks whether to keep its items, and items in use by an experiment are never removed. A plugin can never mark, unmark or grant access to a dataset.
- **Global search finds the exact place.** One palette, scopes All, Experiments, Projects, Datasets, Customize, Runs and People. A result opens the exact place, for example a trial inside its thread.
- **The model provider is a field on an agent.** It is not a connector category. Agents belong to infrastructure.
- **Evaluation templates are added under Customize** and picked when an experiment is started.

## Settled 16 Nov (target)

Decided by the owner, 16 Nov, on the recommendations.

- **Connector credentials are registered once, not minted per run.** The customer registers a read-only credential per connector that leaves the holdout out, and a separate one for the evaluator that includes it. Both are kept in the agent platform's credential store, never in Ratchet. No connector admin secret is anywhere in Ratchet. Short-lived credentials minted per run may come later, connector by connector, self-hosted first, and need a new ruling.
- **Ratchet cloud uses only Ratchet's platform accounts at launch.** An enterprise cannot bring its own platform accounts to Ratchet cloud yet. The adapters support customer accounts anyway, because self-hosted needs them. An enterprise that needs data read in its own network self-hosts, for example with AgentCore in its own AWS account.
- **Five agent platforms, in this order.** Claude Managed Agents, AWS AgentCore, the OpenAI Agents API, Microsoft Foundry Agent Service, then Google Agent Runtime, all behind the one platform trait. The trait is designed against all five from the start, and the spike runs on all five.
- **"This machine" is deferred.** The Mac app is a client of the server's API only. Agents never run on a Mac until a later ruling, which comes after the first platform ships. Measuring never runs on a laptop either way.
- **No Helm chart and no OpenTofu at launch.** The self-hosted server ships as Docker Compose only. Ratchet cloud ships with the Cloudflare config and `cf`. Ratchet's own platform accounts are set up by hand, written down, and owned by the owner. Either tool comes back only with a new ruling.

## Open, ask the owner

Write these as options with a recommendation when they come up. Do not pick one by building it.

- **Who brings the benchmark?** Does Ratchet draft the benchmark, or do engineers bring it?
- **Offline or production results.** Is scoring offline only, or are production results used too?
- **Reshaping data.** Does Ratchet ever reshape data? Today the answer is no (see [non-goals](non-goals.md)).
- **"Try a demo".** Does it stay in the web app? It runs on the simulation, which is a developer and demo tool.
- **The licence.** The workspace manifest says `UNLICENSED` today. What it becomes is not decided.
