Sessions copy Claude Code cloud sessionsA runner polls a queue, claims a session with a lease and runs it in one container. Nothing connects inward. This replaces the agent platforms and their adapters.
Decided20 Nov
OpenCode is the harnessAn agent is OpenCode with one model. The runner writes its machine-wide config. Other harnesses come later through the same runner.
Decided20 Nov
One proxy, the organization's model keysKeys are saved per organization per provider and never sent into a session. The proxy swaps a short-lived token for the key, books spend and refuses calls once the budget is spent.
Decided20 Nov
The holdout runs in a fresh containerA holdout measurement never runs in the agent's machine. It runs in a second container of the same environment version, and only that container gets the holdout data.
Decided20 Nov
No infrastructure tool in the productThe agent writes and runs OpenTofu or any other tool itself, inside the session's machine. The product keeps no template and no state.

Decided16 Nov
A chat and a judgeAntilog is a chat and a judge. A person talks to a coding agent in one machine with repos attached. The judge is a set of tools every session gets: only its numbers count, and only a measured win becomes a pull request. No modes, no plan step, no loop on the server.
Decided16 Nov
Three objectsA session is one agent in one machine, with repos attached. An experiment is a sealed definition of better plus everything measured against it, and a session always belongs to one. A measurement is the judge's signed result for one trial, and a trial is one measure call. Scoreboard, wins, receipts, value and Return are views over measurements.
Decided16 Nov
The toolsEvery session gets seal, measure, history, spawn, deliver and watch, and four setup tools: attach_repo, request_credential, set_environment and request_budget. The same tools are served by antilog mcp to an agent a person already uses on their own machine. measure returns a ticket and the result arrives later.
Decided16 Nov
Settings are toolsA person approves the tool calls that matter. Setup happens in the chat, when it is needed, as a card. Settings pages list what was approved and revoke it. Two things are still set up in Settings: model keys, and members with sign-in.
Decided16 Nov
Approval cards and policyEight card kinds: Seal experiment, Raise budget, Add credential, Attach repo, Change environment, Open pull request, Keep going? and Continue on another agent?. Policy per kind is Always ask, Allow up to a limit or Allow. Add credential always asks, because a person types the value into a secure form. Owners and editors approve, viewers approve nothing.
Decided16 Nov
The judge's trust rulesOnly the judge's numbers count. An agent never reaches the holdout. A sealed experiment never changes. Only the acceptance criteria can mark a win, as one pure function in code. Chat can change what an agent tries and never what counts.
Decided16 Nov
The anti-cheat is in the judgeA sealed experiment; the holdout measured in a fresh container of the same environment; seal checks before sealing (baseline, noise, planted cheats); confirmation on the holdout before Kept, with a bar that rises with the trials tried; a second opinion from a different provider; and a signed receipt.
Decided16 Nov
What an agent seesThe measured value and guardrail values on the evaluation data, and the outcome. It may read the evaluation's code and may never change it. It never reads the holdout or learns a holdout value. This replaces the earlier rule that an agent never reads the evaluation's code.
Decided16 Nov
Kept, and the eight outcomesA trial is Kept when it beats what it started from by more than the bar, every guardrail holds, and it is confirmed in a fresh container and on the holdout. Outcomes: Measuring, Kept, Within noise, Worse, Guardrail failed, Failed holdout, Rejected, Failed.
Decided16 Nov
SessionsOne agent per session, any number of repos, a trial is a set of commits. Git is the hand-off: a short-lived token per repo pushes only to the session's own branch. The agent drives and the server runs no loop. The machine is temporary and the conversation is not.
Decided16 Nov
Spawned sessionsA session may spawn others on the same experiment and budget, on any agent. A spawned session cannot spawn. The parent is told when one finishes and a person can open any of them. No agent's vendor is privileged, because only the judge decides.
Decided16 Nov
BudgetsOne budget per experiment, covering all its sessions and their judge time. Spend is model tokens, machine time and judge time. A person sets it and can change it at any time, and request_budget asks for more by a card. When it is spent the judge refuses measure and the session is Waiting for you. The organization has a default budget and a monthly cap.
Decided16 Nov
Delivery, watch and memorydeliver opens one pull request per repo changed, each with the receipt, and refuses any trial that is not Kept. The session stays attached to reviews and checks. watch measures again, and a regression wakes a session. history is the memory, failures included.
Decided16 Nov
Antilog never holds the dataIds, versions, numbers, states, the conversation's words and audit rows only. Never tool output, file contents, diffs or data. Agents' code reads data only inside the session's machine, and the holdout only in a fresh container.
Decided16 Nov

Customize, Evaluations, Skills, Plugins, Connectors and Agents pages became setup tools with Settings listing them. Plugins, skill packs, notes, Pause agent, projects and the dashboard page are cut. The three basics became session, judge and organization. Evaluator became judge.
