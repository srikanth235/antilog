Decisions

The owner's calls, newest first, each dated. A decision here is settled; an open one is a question to put to the owner, not to guess.

Decided · 16 Nov

Decided16 Nov
A chat and a judgeRatchet is a chat and a judge. A person talks to a coding agent in a sandbox with repos attached. The judge is a set of tools every session gets: only its numbers count, and only a measured win becomes a pull request. No modes, no plan step, no loop on the server.
Decided16 Nov
Three objectsA session is a chat with one agent in one sandbox. A contract is a sealed definition of better. A measurement is the judge's signed result for one trial, and a trial is one measure call. Scoreboard, wins, receipts, value and Return are views over measurements.
Decided16 Nov
The toolsEvery session gets seal, measure, history, spawn, deliver and watch, and four setup tools: attach_repo, request_credential, set_environment and request_budget. The same tools are served by ratchet mcp to an agent a person already uses on their own machine. measure returns a ticket and the result arrives later.
Decided16 Nov
Settings are toolsA person approves the tool calls that matter. Setup happens in the chat, when it is needed, as a card. Settings pages list what was approved and revoke it. Two things are still set up in Settings: agent platform accounts, and members with sign-in.
Decided16 Nov
Approval cards and policySix card kinds: Seal contract, Raise budget, Add credential, Attach repo, Change environment, Open pull request. Policy per kind is Always ask, Allow up to a limit or Allow. Add credential always asks, because a person types the value into a secure form. Owners and editors approve, viewers approve nothing.
Decided16 Nov
The judge's trust rulesOnly the judge's numbers count. An agent never holds the holdout credential. A sealed contract never changes. Only the acceptance criteria can mark a win, as one pure function in code. Chat can change what an agent tries and never what counts.
Decided16 Nov
The anti-cheat is in the judgeA sealed contract; a fresh judge sandbox for every measurement; seal checks before sealing (baseline, noise, planted cheats); confirmation on the holdout before Kept, with a bar that rises with the trials tried; a second opinion from a different provider; and a signed receipt.
Decided16 Nov
What an agent seesThe measured value and guardrail values on the evaluation data, and the outcome. It may read the evaluation's code and may never change it. It never reads the holdout or learns a holdout value. This replaces the earlier rule that an agent never reads the evaluation's code.
Decided16 Nov
Kept, and the eight outcomesA trial is Kept when it beats what it started from by more than the bar, every guardrail holds, and it is confirmed in a fresh judge sandbox and on the holdout. Outcomes: Measuring, Kept, Within noise, Worse, Guardrail failed, Failed holdout, Rejected, Failed.
Decided16 Nov
SessionsOne agent per session, any number of repos, a trial is a set of commits. Git is the hand-off: a short-lived token per repo pushes only to the session's own branch. The agent drives and the server runs no loop. The sandbox is temporary and the conversation is not.
Decided16 Nov
Spawned sessionsA session may spawn others on the same contract and budget, on any agent and platform. A spawned session cannot spawn. The parent is told when one finishes and a person can open any of them. No agent's vendor is privileged, because only the judge decides.
Decided16 Nov
BudgetsOne budget per session and the sessions it spawns. Spend is model tokens, sandbox time and judge time. A standing allowance comes from policy and request_budget raises it by a card. When it is spent the judge refuses measure and the session is Waiting for you. The organization has a monthly cap.
Decided16 Nov
Delivery, watch and memorydeliver opens one pull request per repo changed, each with the receipt, and refuses any trial that is not Kept. The session stays attached to reviews and checks. watch measures again, and a regression wakes a session. history is the memory, failures included.
Decided16 Nov
Ratchet never holds the dataIds, versions, numbers, states, the conversation's words and audit rows only. Never tool output, file contents, diffs or data. Agents' code reads data only inside a platform's sandbox, and the holdout lives only in the judge's credential.
Decided16 Nov
What this replacesExperiments, and runs as numbered executions, became sessions on a contract. Drafts, drafting sessions, the config branch and the stepper became cards. Customize, Evaluations, Skills, Plugins, Connectors and Agents pages became setup tools with Settings listing them. Plugins, skill packs, notes, Pause agent, projects and the dashboard page are cut. The three basics became session, judge and organization. Evaluator, evaluator sandbox and measuring platform became judge, judge sandbox and judge platform.
Decided16 Nov
Five agent platformsClaude Managed Agents, AWS AgentCore, OpenAI Agents API, Microsoft Foundry Agent Service, then Google Agent Runtime, in that build order, behind one agent trait with one adapter each. Unchanged. The spike runs on all five before product code.
Decided16 Nov
Ratchet cloud manages the platforms at costOn Ratchet cloud we use our own platform accounts and bill at cost through each session's budget. The Agent platforms page is read-only there and shows data and retention per platform. Unchanged.
Decided16 Nov
Self-hosted uses your platform accountsAn owner adds the organization's own accounts under Settings, Agent platforms, with Add platform. Credentials stay in the platform's credential store. Unchanged.
Decided16 Nov
The judge platformThe judge sandbox runs on a platform that can run a command with no agent. AWS AgentCore can. Google Agent Runtime is checked in the spike. The other three cannot. The platform that hosts judge sandboxes carries the Judge platform badge.
Decided16 Nov
Connector credentials are registered onceRead-only, registered once by the customer and kept in the platform's credential store. Ratchet keeps no connector secret and no secret manager reference. Unchanged.
Decided16 Nov
This machine is deferred; no Helm or OpenTofuAgents never run on a Mac, and the Mac app is only a client. Self-hosted is Docker Compose, and Ratchet cloud ships with the Cloudflare config. Unchanged.

Decided15 Nov
Real logos for named productsAgents, connectors, model providers, clouds and sign-in providers show their own real logo from a credible source. Never a text tile. Ratchet's own concepts keep our glyphs.
Decided15 Nov
Postgres self-hosted, SQLite in the cloudOne core, two shells. Self-hosted servers use Postgres, Ratchet cloud uses one SQLite database per organization. Both are supported from day 0.
Decided15 Nov
Browser supportCurrent and previous Chrome, Edge, Firefox and Safari on desktop. Newly available features only with a light fallback and no polyfill package.
Decided15 Nov
Base UI for componentsThe web client builds on Base UI. Each part is wrapped once in our components folder so features never import the library directly. Only what Base UI lacks is built natively.
Decided15 Nov
Installable web app on Windows and LinuxmacOS gets the native app. On Windows and Linux the web app installs as a progressive web app: own window, badge, push and an offline screen. It caches the app only, never data.
Decided15 Nov
Notifications are inFor a win, Waiting for you, a regression and a budget spent. Native on the Mac, web push elsewhere, ids only. No email or chat for now.
Decided15 Nov
The Mac app updates with SparkleA direct download, signed with a Developer ID and notarized, updated with Sparkle. Not on the Mac App Store. Companies can still deploy it with their device management.
