The judge

Only the judge's numbers count.

An agent can try anything. It cannot mark its own win, change what is measured, or see the data held back to check it.

Seal the experiment

The metric, the evaluation and the protected files are fixed before the first trial. A trial that changes a protected path is Rejected.

Fresh judge sandbox

Every measurement runs in a new sandbox the agent never touches, with the trial and its starting point run side by side.

A holdout it never sees

Kept needs a confirmation on data the agent cannot read. The judge's credential is separate from the agent's.

A signed receipt

Every win carries a receipt anyone can verify, and a pull request opens only for a Kept trial.

How it works

A goal, a seal, a measurement, a pull request.

The chat works like a coding agent on the web, with your repos attached. The agent drives. The judge measures.

01

State a goal

Say what should get better, in the chat. The agent works in a sandbox with your repos attached.

02

Seal it

The goal becomes a sealed experiment, and the seal checks prove it can tell a gain from noise.

03

Measure

The agent asks the judge to measure each change. It keeps what wins and drops what does not.

04

Open a pull request

A Kept trial opens one pull request per repo, with its receipt. People review it as they would any other.
